STAGE 01

SQLGlot reads the dialect.

Every incoming Snowflake statement is parsed into an AST and transpiled toward BigQuery syntax. Anything SQLGlot can't resolve outright is captured as a structured error, not a crash.

-- Snowflake source SELECT o.order_id, IFF(o.status = 'CANCELLED', 0, o.total_amount) AS billable_amount, DATEADD('day', -30, o.order_date) AS lookback_date FROM orders o;
STAGE 02

GPT-5.5 heals what syntax alone can't.

Snowflake idioms with no direct BigQuery equivalent — IFF, DATEADD, LISTAGG — get rewritten by an LLM correction pass, then re-parsed. Up to 3 retries, self-driven.

1

Detect

Transpile error surfaces the unsupported construct and its position.

2

Correct

GPT-5.5 rewrites just the offending fragment, preserving semantics.

3

Re-parse

Corrected SQL runs back through SQLGlot for validation.

4

Converge

Loop exits the moment the query parses clean — or after 3 tries.

STAGE 03

A dry run, not a gamble.

The corrected query is validated against BigQuery's dry-run API — zero bytes billed, zero data touched, full confidence it will run.

STAGE 04

Every column, traced.

Column-level lineage is extracted before and after migration. If billable_amount stops tracing back to the same source columns, the agent flags it — before it reaches production.

## Lineage Drift - billable_amount: orders.total_amount, orders.status - lookback_date: orders.order_date -- 0 unexplained changes across 1,204 queries
STAGE 05

Thousands of queries. One async loop.

Every query above runs concurrently through the same pipeline — parse, heal, execute, trace — bounded by a semaphore so BigQuery quotas stay respected.
